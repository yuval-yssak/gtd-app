Stale-chunk / deploy-survival fixes (2026-11-10, fix/stale-chunk-reload: lazyChunkLoaders + idle warm-up) were scoped on the premise "only two lazy chunks". The build actually emits ~100 more: `markdown({ codeLanguages: languages })` makes every fenced-code language a dynamic import inside node_modules. A source scan of `lazy(() => import(` cannot see them.

**Why:** after a deploy those chunk URLs die too; CodeMirror catches the rejection (logException) and just skips highlighting that fence, so it degrades rather than crashes — but nobody documented that it is deliberately uncovered.

**How to apply:** for any chunk/deploy/offline-precache change, list `dist-e2e/assets` (or a build) rather than trusting the stated chunk count; check node_modules dynamic imports and the failure mode of each.
